# 프로젝트: 사단(Sadan) 웹사이트 기획 및 자동 리서치 에이전트 지시서 v2.6

본 지시서는 단순한 "좋은 사이트 수집"이 아닌, 사단 브랜드에 적용 가능한 "다양하고 차별화된 UX 구조 및 레이아웃 확보"를 목표로 한다. 억지 수집(Quantity Padding)을 절대 금지하며, 개수보다 '구조적 다양성'을 최우선으로 한다.

---

## 1. 브랜드 컨텍스트 (Brand Identity)

* **브랜드명:** 사단 (士團)
* **브랜드 정의:** 조선 암행어사의 마패 헤리티지를 현대적으로 재해석한 커스텀 레이어링 향수 브랜드
* **핵심 가치:** 유일성, 실용성, 스토리텔링
* **디자인 무드:** 오리엔탈 모던 (Oriental Modern). 한지, 스톤, 자연적 질감과 견고하고 맑은 투명 용기의 시각적 대비. 정갈하고 차분한 미니멀 룩앤필.

---

## 2. 리서치 핵심 전략

에이전트의 리서치 목표는 단순한 사이트 수집이 아닌, 사단 브랜드에 적용 가능한 **다양하고 차별화된 UX 구조 및 레이아웃 확보**이다.

단순히 미적으로 우수한 사이트가 아니라, 실제로 서비스 기획 및 프론트엔드 설계에 활용 가능한 구조적 인사이트를 제공해야 한다.

---

## 3. 필수 검증 규칙 (Strict Validation Rules)

### 3-1. 링크 유효성 검증

다음 조건을 만족하지 않는 경우 즉시 제외하며 수집하지 않는다:

* HTTP 상태 코드 200이 아닌 경우
* 페이지 로딩 실패 (timeout, DNS 오류 포함)
* 리디렉션 오류 또는 dead link
* 콘텐츠가 정상적으로 렌더링되지 않는 경우

---

### 3-2. 중복 제거 규칙 및 사전 검증 (강화됨)

신규 사이트 수집 전 반드시 기존 결과를 비교하며 아래 규칙을 모두 적용한다:

#### 1. 도메인 기준 강제 필터

* **Root Domain 기준 1개만 허용 (절대 규칙)**

다음은 모두 동일 사이트로 간주하고 전부 제외:

- `brand.com / brand.co.kr / brand.jp / brand.cn`
- `kr.brand.com / us.brand.com`
- `brand.com/kr / brand.com/en`
- `shop.brand.com / store.brand.com`
- `brand.com?lang=kr`

---

#### 2. 페이지 단위 수집 금지 (핵심)

다음은 전부 동일 사이트로 간주:

* 메인 페이지
* 서브페이지 (about, product, campaign 등)
* 룩북 / 에디토리얼
* 이벤트 / 프로모션 페이지
* 제품 상세 페이지

→ **사이트 단위 1개만 수집 (페이지 단위 수집 절대 금지)**

---

#### 3. 브랜드 단위 중복 금지

동일 브랜드의 다음은 모두 동일로 간주:

* 글로벌 사이트
* 국가별 사이트
* 직영몰
* 리테일몰
* 편집샵 입점 페이지

→ **브랜드당 1개만 허용**

---

#### 4. URL 문자열 무력화 규칙 (중요)

다음이 달라도 동일 사이트로 처리:

* URL path
* query string (?ref=, ?lang= 등)
* language parameter
* trailing slash (/)

→ **“URL이 다르면 다른 사이트”라는 판단 금지**

---

#### 5. 선검증 로직 (필수 수행)

수집 전에 반드시:

1. 현재 도메인이 기존 리스트에 있는지 확인
2. 브랜드명이 기존과 동일한지 확인
3. UI가 아닌 "브랜드 출처" 기준으로 판단

→ 하나라도 겹치면 즉시 제외

---

### 3-3. 디자인 필터링 (배제 대상)

다음 유형은 수집 금지:

* 과도한 3D / WebGL 중심 사이트
* UX보다 연출이 우선인 사이트
* 원페이지 풀스크린 스크롤형 (정보 탐색 방해)
* 과도한 비대칭 레이아웃
* 이솝(Aesop) 스타일 복제 사이트
* 니치 향수 브랜드 편중 수집

---

### 3-4. UX 구조 중복 금지 및 다양성 확보 (강화됨)

시각이 아닌 **사용자 탐색 흐름 구조 기준으로 판단**

다음 요소 중 2개 이상 동일하면 동일 구조로 간주:

* Navigation depth
* 콘텐츠 흐름
* Grid 시스템
* CTA 위치
* 사용자 행동 흐름
* 인터랙션 방식

---

#### 추가 강제 규칙

* 동일 카테고리 내 동일 구조 **2개 초과 금지**
* “비슷한 느낌”이 아닌 “같은 흐름”이면 제거
* 다양성 확보 안 되면 → **수량 부족 상태 유지**
* 억지로 채우는 행위 금지

---

## 4. Phase 1: 디자인 구간

### Step 1. 자동 리서치 수행

각 카테고리별로 최소 3개 이상의 웹사이트를 자동으로 탐색하고 수집한다.

---

### Step 2. 자동 리서치 출력 포맷

각 사이트는 반드시 다음 형식으로 정리:

* **브랜드 이름:**
* **링크:** (루트 도메인 기준 URL)
* **주요 프론트엔드 기능:**
* **적합한 이유:**

---

### Step 3. 리서치 결과 3단 분류

수집된 사이트를 아래 3가지 카테고리로 분류:

---

#### 1. 벤치마킹 핵심 사이트

* 사단 프로젝트에 직접 적용 가능한 UX/UI 구조
* 정보 구조 / 인터랙션 / 콘텐츠 흐름이 우수한 사이트

---

#### 2. 레퍼런스 사이트

* 부분적으로 참고할 가치가 있는 요소 보유
* 특정 기능 / 레이아웃 / 인터랙션만 유효

---

#### 3. 제외 사이트

* 기준 미달
* UX 중복
* 접근 불가
* 구조적 활용도 낮음

---

## 5. Phase 2: 설계 구간

### Step 1. 정보 구조(IA) 설계

* 메인 / 서브 페이지 구조 정의
* 사용자 플로우 설계
* 콘텐츠 위계 구조화

---

### Step 2. UI/UX 와이어프레임 설계

* 핵심 페이지 레이아웃 설계
* 주요 인터랙션 정의
* 반응형 구조 고려

---

### Step 3. 결과물(파일) 생성

다음 파일 생성:

* `research.md`
* `ia.md`
* `wireframe.md`

---

### 저장 전 필수 검증

* 도메인 중복 검사
* 브랜드 중복 검사
* UX 구조 중복 검사

→ 하나라도 걸리면 저장 금지

---

## 6. 실패 조건 및 핵심 목표 (강화됨)

다음 발생 시 전체 결과 실패 처리:

* 동일 사이트의 다른 페이지 포함
* 동일 브랜드의 국가별 사이트 포함
* URL만 다른 동일 사이트 포함
* UX 구조 반복
* 접속 불가 링크 포함
* 구조 다양성 부족
* 억지 수집

---

## 7. Final Duplicate Audit (최종 필수 단계)

파일 생성 직전 반드시 수행:

1. Root Domain 기준 중복 검사
2. 브랜드 기준 중복 검사
3. URL 구조 무시 후 동일성 재검증
4. UX 흐름 기준 구조 중복 검사

→ 하나라도 중복이면 삭제 후 재수집

---

## 8. 최종 응답 규칙

* 모든 결과는 Markdown 형식으로 출력
* 불필요한 설명 없이 결과 중심으로 작성
* 억지 개수 채우기 금지
* 기준 미달 시 “부족 상태” 그대로 제출

---

## 핵심 목표 요약

이 프로젝트의 목표는:

> “좋은 사이트 많이 찾기”가 아니라  
> **“겹치지 않는 UX 구조 확보”이다**
