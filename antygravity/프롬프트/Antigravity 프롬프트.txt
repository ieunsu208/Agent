[1. 사이트맵 제작]

현재 작업 폴더를 기준으로 아래 작업을 수행해줘.

- 입력 파일: []
- 결과물 저장 폴더: []

입력 파일의 브랜드 정보, 사용자 유형, 사용자 목표, 주요 기능, 콘텐츠와 분석 결과를 빠짐없이 읽고 사이트맵을 설계해줘. Figma를 생성하거나 수정하지 말고, CLI에서 바로 확인하고 다른 도구에서도 재사용할 수 있는 로컬 파일로 결과물을 만들어줘.

다음 파일을 UTF-8 인코딩으로 생성해줘.

1. `사이트맵.md`
   - 프로젝트 개요
   - 설계 근거와 핵심 사용자 목표
   - 전역 내비게이션 구조
   - 계층형 사이트맵
   - 페이지별 목적, 핵심 콘텐츠, 주요 기능, 연결 페이지를 정리한 표
   - Mermaid `flowchart` 문법으로 작성한 사이트맵
2. `사이트맵.mmd`
   - `사이트맵.md`에 사용한 Mermaid 코드만 포함
3. `사이트맵.svg`
   - 한글이 깨지지 않고 확대해도 읽을 수 있는 벡터 형식

작성 규칙:

- 페이지를 1차, 2차, 3차 깊이로 구분하고 상위·하위 관계를 명확히 표시해줘.
- 공통 영역, 회원 상태별 영역, 주요 사용자 여정, 예외 페이지를 구분해줘.
- 입력 파일에 없는 사실은 임의로 확정하지 말고 `가정`으로 표시해줘.
- 링크가 끊긴 페이지와 중복 페이지가 없도록 검토해줘.
- 작업 완료 후 생성한 파일의 상대 경로와 각 파일의 용도를 짧게 출력해줘.

[2. 서비스 흐름도 제작]

현재 작업 폴더를 기준으로 아래 작업을 수행해줘.

- 사이트맵 입력 파일: [클라이언트 모음\신규_클라이언트1_윤태양.md]
- 추가 참고 파일: [전체 사이트맵\1윤태양\사이트맵]
- 결과물 저장 폴더: [전체 사이트맵\1윤태양\서비스_흐름도]

입력 파일을 모두 읽고 사이트 구조와 핵심 사용자 목표를 기반으로 서비스 흐름도를 설계해줘. Figma를 생성하거나 수정하지 말고, CLI에서 바로 확인하고 다른 도구에서도 재사용할 수 있는 로컬 파일로 결과물을 만들어줘.

다음 파일을 UTF-8 인코딩으로 생성해줘.

1. `서비스_흐름도.md`
   - 서비스 흐름 개요
   - 사용자 유형과 시작 조건
   - 핵심 정상 흐름
   - 분기, 오류, 이탈, 재진입 흐름
   - 단계별 사용자 행동, 시스템 처리, 화면, 다음 조건을 정리한 표
   - Mermaid `flowchart` 문법으로 작성한 전체 서비스 흐름도
2. `서비스_흐름도.mmd`
   - `서비스_흐름도.md`에 사용한 Mermaid 코드만 포함
3. `서비스_흐름도.svg`
   - 시작·종료, 사용자 행동, 시스템 처리, 판단 분기를 서로 다른 도형으로 구분한 벡터 형식

작성 규칙:

- 시작점과 종료점을 명확히 표시해줘.
- 주요 흐름은 `탐색 → 선택 → 상세 확인 → 핵심 행동 → 결과 확인`처럼 순서가 보이게 구성해줘.
- 로그인 여부, 입력값 오류, 결과 없음, 이전 단계 이동과 같은 필수 분기를 포함해줘.
- 모든 화면 이름은 사이트맵의 페이지 이름과 일치시켜줘.
- 연결이 끊긴 단계나 도달할 수 없는 화면이 없는지 검토해줘.
- 작업 완료 후 생성한 파일의 상대 경로와 각 파일의 용도를 짧게 출력해줘.

[3. 화면 설계서 제작]

현재 작업 폴더를 기준으로 아래 작업을 수행해줘.

- 사이트맵 입력 파일: [전체 사이트맵\1윤태양\사이트맵]
- 서비스 흐름도 입력 파일: [전체 사이트맵\1윤태양\서비스_흐름도]
- 추가 참고 파일: [클라이언트 모음\신규_클라이언트1_윤태양.md]
- 결과물 저장 폴더: [전체 사이트맵\1윤태양\화면_설계서]

입력 파일을 모두 읽고 사이트맵과 서비스 흐름도에 등장하는 화면 전체를 대상으로 화면 설계서를 제작해줘. Figma를 생성하거나 수정하지 말고, 문서와 브라우저에서 확인 가능한 저충실도 와이어프레임 파일로 결과물을 만들어줘.

다음 파일을 UTF-8 인코딩으로 생성해줘.

1. `화면_설계서.md`
   - 프로젝트 및 설계 범위
   - 화면 ID 규칙과 전체 화면 목록
   - 화면별 목적, 진입 조건, 종료 조건
   - 화면 구성 영역과 UI 요소
   - 표시 데이터, 사용자 행동, 인터랙션, 이동 대상
   - 기본·로딩·빈 상태·오류·완료 상태
   - 유효성 검사와 오류 메시지
   - PC·태블릿·모바일 반응형 기준
   - 접근성 요구사항
2. `와이어프레임.html`
   - 외부 라이브러리 없이 브라우저에서 단독 실행 가능한 HTML/CSS/JavaScript 파일
   - 화면별 저충실도 와이어프레임과 화면 ID·이름 표시
   - 상단 목차 또는 사이드바에서 각 화면으로 이동 가능
   - 버튼과 링크를 누르면 서비스 흐름에 맞는 화면으로 이동
   - 모바일, 태블릿, 데스크톱 레이아웃을 확인할 수 있는 반응형 구성
3. `화면_목록.json`
   - 각 화면의 `id`, `name`, `purpose`, `entryConditions`, `sections`, `actions`, `states`, `nextScreens`를 포함한 유효한 JSON

작성 규칙:

- 사이트맵과 서비스 흐름도에 정의된 화면 이름과 이동 관계를 그대로 사용해줘.
- 화면마다 고유한 화면 ID를 부여하고 세 결과물에서 동일하게 유지해줘.
- 공통 헤더, 푸터, 내비게이션과 반복 컴포넌트는 일관되게 적용해줘.
- 이미지 영역은 대체 텍스트가 있는 플레이스홀더로 표현해줘.
- 입력 파일에 없는 상세 정책은 `가정`으로 표시하고 설계서에 따로 모아줘.
- HTML의 모든 내부 이동, 주요 버튼, 반응형 레이아웃과 JSON 문법을 검사해줘.
- 작업 완료 후 생성한 파일의 상대 경로, 실행 방법, 검증 결과를 짧게 출력해줘.

[4. 메인페이지 스토리보드 제작]

현재 작업 폴더를 기준으로 아래 작업을 수행해줘.

- 사이트맵 입력 파일: [전체 사이트맵\1윤태양\사이트맵]
- 서비스 흐름도 입력 파일: [전체 사이트맵\1윤태양\서비스_흐름도]
- 화면 설계서 입력 파일: [전체 사이트맵\1윤태양\화면_설계서]
- 클라이언트 기획 브리프: [가상 클라이언트\클라이언트 모음\신규_클라이언트1_윤태양.md]
- 브랜드 웹페이지 레퍼런스 분석: [메모\master_references1.txt] 및 [메모\master_references2.txt]
- 결과물 저장 폴더: [스토리보드 결과]

입력 파일을 모두 읽고 폴더 안의 설계 파일들과 브랜드 웹페이지 레퍼런스 분석 데이터(이솝, 르라보, SW19, 탬버린즈, 논픽션, 팝업 플랫폼 등)를 기반으로 메인페이지(P-MAIN-01) 스토리보드를 작성해줘. Figma를 생성하거나 수정하지 말고, CLI에서 바로 확인하고 다른 도구에서도 재사용할 수 있는 로컬 파일로 결과물을 만들어줘.

다음 파일을 UTF-8 인코딩으로 생성해줘.

1. `메인페이지_스토리보드.md`
   - 프로젝트 개요 및 선택된 6대 레퍼런스 레이아웃 아키타입(Type 1~6) 구조 표
   - 화면 1개당/섹션 1개당 상세 표 형식 스토리보드 명세 (화면 ID, 영역명, 노출 조건, UI 구성 요소, 표시 데이터, 사용자 행동, 시스템 처리, 이동 대상)
   - 상태별 UI 표(기본/로딩/오류/완료) 및 접근성/반응형 명세 표
2. `메인페이지_스토리보드.html`
   - 외부 라이브러리 없이 브라우저에서 단독 실행 가능한 회색 박스/글자 중심 스토리보드 와이어프레임 뷰어
   - 획일적 상하 블록 구조 전면 배제 및 선택된 레퍼런스 아키타입에 최적화된 고유 CSS Grid/Flex 쉘 구현
3. `스토리보드_목록.json`
   - 각 스토리보드 표 항목의 `id`, `name`, `section`, `uiComponents`, `userActions`, `systemLogic`, `nextScreen`을 포함한 유효한 JSON

작성 규칙:

- [획일적 템플릿 사용 전면 금지]: 모든 클라이언트에 동일한 Header-GNB-Hero-3열카드-Aside 구조 사용을 금지하고, 브랜드 분석 웹페이지 레퍼런스 중 클라이언트 비즈니스 목적에 맞는 6대 아키타입 중 1개를 필수로 1:1 매핑하여 구현해줘.
- [클라이언트 맞춤 제품 쇼케이스 필수 배치]: 메인 상단 핵심 영역에 실물 제품/키트/굿즈 쇼케이스를 회색 박스로 전면 배치해줘.
- 메인페이지의 각 구역을 화면 1개당/섹션 1개당 완벽한 독립 표(Table) 형식으로 명확히 구별해서 작성해줘.
- 공통 헤더, 푸터, 내비게이션과 반복 컴포넌트는 일관되게 적용해줘.
- 입력 파일에 없는 상세 정책은 `가정`으로 표시하고 스토리보드에 따로 모아줘.
- HTML의 모든 내부 이동, 주요 버튼, 반응형 레이아웃과 JSON 문법을 검사해줘.
- 작업 완료 후 생성한 파일의 상대 경로와 각 파일의 용도를 짧게 출력해줘.
